# 兴趣发现、收藏门槛与更新提醒

2026-10-07：根据用户澄清，主产品不是手动语义搜索资料库，而是主动发现并由用户决定保存。
本文件的发现控制面板/每日开关任务是历史版本；当前简洁界面与连续流请看 [新学习任务](simple-feed-learning.md)。收藏及版本证据原则仍适用。

## 数据与文件

`ContentItem/Version/Occurrence` 是候选缓存及证据，采集不代表收藏。
`Favorite.active=true` 才是长期库成员；迁移不会自动收藏原有内容。
`DiscoverySettings` 保存近期明确主题、运行小时、检索词发送同意和匹配方式，不冒充行为画像。
`DiscoveryRun` 保存状态和配置快照；`Recommendation` 保存当时版本、理由与分项分数。
`UpdateNotice` 保存收藏后实际变化及来源版本，不以活跃/抓取时间单独触发。

- `app/discovery/api.py`：设置、手动执行、推荐快照、更新检查。
- `app/discovery/service.py`：有限外部查询、来源更新、内部匹配、栏目分配与缺口报告。
- `app/services/favorites.py`：材料比较与幂等提醒。
- `app/api.py`：收藏门槛、候选/长期库筛选、提醒读取。
- `app/workers/tasks.py`：执行及每日到期检查；Compose Beat 只部署一个实例。
- `frontend/src/DiscoveryPanel.tsx`：今日推荐与显式运行配置。
- `frontend/src/UpdatesPanel.tsx`：更新提醒，不意味着检查了全文。

## 任务 1：证明采集不等于收藏

输入：一个可访问 RSS，未收藏的候选。输出：候选池有内容，长期库没有它。
知识：内容身份与用户收藏关系、外键、筛选 SQL、PUT 幂等。
验收：收藏两次不创建两个 Favorite；取消收藏不删除版本。检查
`PUT /api/items/{id}/favorite`，分别读取 `scope=candidates` 和 `scope=library`。
不要为练习清空真实资料；自动测试使用随机隔离 schema。

## 任务 2：外部发现与独立固定栏目

输入：近期主题、长期方向、固定栏目、RSS；可选明确允许 GitHub 检索词外发。
输出：可检查的 DiscoveryRun 和最多 10 条推荐，收藏保持不变。
知识：平台关键词搜索不同于向量匹配；异步任务、配置快照、OR/AND、有限预算。
验收：近期兴趣改变，固定栏目仍独立；屏蔽优先，缺口显示，不用无关结果凑数。
目前关键词/屏蔽采用字面基线，无语义屏蔽、难度模型或相邻探索。
来源节选不是 AI 要点摘要，难度显示未评估。

## 任务 3：Embedding 在内部解决什么

输入：同候选、同主题，分别运行规则/本地模式。输出：规则分数及语义相似度。
知识：预训练推理、L2、余弦、模型空间和阈值。
验收：跟踪 `semantic_scores`；候选版本向量缓存后不重复计算文档，主题仍需编码。
仅使用标题前 200 字符、正文前 600 字符，不能说读过全文。
0.55 是实验阈值，不是训练出的边界或 55% 相关概率。
正式比较需同候选/同输入人工标注，模拟向量只证明流程，不证明效果提升。

## 任务 4：更新不是抓取时间变化

输入：隔离测试中已收藏材料，修改正文，再只修改 updated_at。
输出：正文变化提醒一次；重复抓取/活动时间变化不增加提醒。
知识：快照和业务事件、幂等键、收藏时间边界、材料获取范围。
验收：`uv run pytest tests/test_discovery_favorites.py -v`；收藏仓库的新 Release 可提醒，
历史 Release 不补发。阅读打开推荐/提醒所依据版本，不偷换为最新内容。
移出 RSS 的文章、通用网页全文和新论文版本目前不能保证跟踪。

## 任务 5：每日执行与有限缓存

输入：显式开启开关、北京时间小时、持续运行电脑/Docker。输出：当天最多一个自动记录。
知识：Beat、UTC/北京时间、日期唯一约束与手动恢复。
验收：初始关闭；同一天重复 tick 或重启 Beat 不创建第二个自动运行。
恢复后只补当天，不补全部历史日、不唤醒电脑；失败可手动重试，不是 exactly-once。
没有兴趣、启用栏目或收藏时，开启每日运行返回 422；仅有收藏时，每日任务只检查收藏更新，不编造兴趣或推荐。
候选可见 30 天；推荐同版本冷却 7 天，不把未点击当负反馈。
**尚不物理清理未收藏正文/向量。**这是保护已有数据的边界，不表示磁盘有硬上限。
