# 阶段二练习：长期画像与固定栏目配置

本文件记录画像配置阶段；2026-10-07 起明确兴趣和栏目已用于发现流程，
见 [兴趣发现学习任务](discovery-and-library-learning.md)，仍无动态行为学习或已验证推荐提升。
复用阶段一的 FastAPI、SQLAlchemy、PostgreSQL 和 React，没有新增服务。

## 为什么分成三张表

`long_term_profiles` 回答“我是谁、想长期学习什么”，保存当前画像。
`profile_revisions` 回答“哪次修改改变了什么”，保存历史快照，便于解释与排错。
`fixed_columns` 回答“即使近期兴趣改变，也必须保留什么”，不嵌在画像 JSON 中，避免被画像整体更新覆盖。

画像字段选择 JSON 是为了小规模迭代；API 使用 Pydantic 严格限制字段与类型。
身份、版本、时间、唯一约束仍是普通数据库列。不是说任意 JSON 都可以写入。
暂不引入用户登录，服务器从现有本地配置读取 user_id，而不是信任请求中传入的用户身份。
查询范围检查不等于完整鉴权，仍只能本地使用。

## 核心数据流

页面加载画像与版本 → 用户修改草稿 → PATCH 携带 expected_version → 校验输入
→ 获取用户级事务锁 → 读取当前版本 → 检查冲突 → 计算真正改变的字段
→ 同一事务保存当前画像和历史快照 → 返回新版本 → 页面更新草稿。

版本解决的是过期页面覆盖，事务锁解决的是并发检查：例如两个页面同时首次创建画像，
或者两个请求分别增加 6 条栏目，必须按顺序检查，不能同时认为自己没超额。
无需为这个单用户场景新引入 Redis 分布式锁。空改动不写历史；异常关闭会回滚并释放事务锁。

画像字段元数据的 `user_explicit` 表示用户明确修改，不代表模型证实了水平。
“基础：Python”不等于系统测试出掌握 Python；阅读预算留空表示未知，而不是零分钟。

## 任务 1：保存并追踪一项真实配置

- 输入：你自己的背景，以及一个真实基础，例如 Python。阅读预算可以留空。
- 输出：页面保存为 v1；字段显示手动修改时间。
- 需要补的知识：HTTP PATCH、JSON、Pydantic 输入校验、React 草稿状态。
- 验收：浏览器开发者工具 Network 中找到 `/api/profile`，请求带 `expected_version: 0`，响应为版本 1。查看历史能看到该快照；相同内容再次保存不增加版本。

定位：`frontend/src/ProfilePanel.tsx` 的 saveProfile；`backend/app/profiles/api.py` 的 patch_profile；`backend/app/profiles/schemas.py` 的 ProfilePatch。

## 任务 2：验证两个页面不能互相覆盖

- 输入：打开两个独立浏览器标签页，各加载同一画像；第一个修改背景并保存，第二个修改目标再保存。
- 输出：第二个返回 409，保留未保存草稿。
- 需要补的知识：乐观并发检查、事务、为什么“最后一次写入获胜”会丢数据。
- 验收：第二个页面没有自动重试或覆盖；复制需要的草稿，再明确重新载入配置，合并修改后可以保存。

不要在两个页面中用同样的最终内容测试：内容完全相同仍可因期望版本过期返回冲突，这个设计优先保护一致性。

## 任务 3：创建一个独立固定栏目

- 输入：名称“网安行业动态”，关键词 security、漏洞、cybersecurity，目标 2 条；来源可不限制。
- 输出：独立栏目保存，页面显示启用状态和版本；目前不会开始推送。
- 需要补的知识：唯一约束、大小写/Unicode 名称规范化、输入条件验证、配额并发。
- 验收：修改长期方向为 AI 后，栏目保持不变；编辑目标或停用栏目也不改变画像版本。空条件、不存在来源、重复名称或启用合计超过 10 会被拒绝。

来源停用不等于栏目停用，资料也不删除。当前发现流程执行关键词组内 OR，再与来源和内容类型限制 AND。
10 条是临时配置上限，不是当前已有的日报策略。接入动态兴趣/探索时需明确总预算、去重计数与份额，不能默认固定栏目占满后仍有探索空间。

## 任务 4：从测试理解“不变量”

- 输入：`backend/tests/test_profiles_integration.py` 与 `frontend/tests/profile.spec.ts`。
- 输出：运行测试，能指出哪些断言保护“画像与栏目互不覆盖”和“并发不超额”。
- 需要补的知识：pytest fixtures、临时 schema、HTTP 模拟、浏览器断言。
- 验收：在 backend 运行 `uv run pytest tests/test_profiles_integration.py -v`；在 frontend 运行 `npm.cmd test`。测试只在隔离 schema 或模拟接口中写数据，不更改你的个人配置。

数据库检查可在本地 API 文档读取 `/api/profile` 和 `/api/profile/history`。
若使用数据库客户端，查询三张新表查看版本与快照即可；不要为了练习清空现有资料或直接改画像 JSON 绕过 API 校验。
