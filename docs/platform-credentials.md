# 网页填写平台凭证

## GitHub 怎么接

1. 打开本地网页侧边栏“来源”，输入 `https://github.com/`，点击“检测接入方式”。
2. 页面显示“GitHub 平台 API”，通过“申请平台凭证”前往 GitHub 官方设置；申请后将 Personal Access Token 填入页面的密码框。不要发送给聊天助手或提交到 Git。
3. 点击“验证平台连接”。提供 Token 时先验证身份，再读取少量公共仓库元数据；不提供时明确使用匿名公开读取。
4. 查看实际内容预览，再点击“验证并保存所选来源”。保存前会再次访问平台验证；失败不会保存半成品连接。
5. 保存后在来源卡片打开“平台工具”，选择列表、搜索、Star 或 Releases；详情读取 README/说明和原始材料。没有绑定某一个仓库，也不等于获得整个 GitHub 的无限访问权限。

凭证权限取决于实际调用端点和资源，应授予最小必要权限；连接验证通过不代表每个端点都可用。参考 [GitHub 官方认证说明](https://docs.github.com/en/rest/authentication/authenticating-to-the-rest-api)。

编辑来源时需重新检测和验证：留空保留原值，输入新值替换，勾选“移除已保存凭证”则改为匿名模式。原 Token 不回显，错误 Token 不自动降级成“连接成功”。新连接匿名模式不会回退使用 `.env` 的 Token。

## 数据和密钥在哪里

Token 经后端使用 [Fernet 认证加密](https://cryptography.io/en/latest/fernet/) 后保存在 PostgreSQL 的来源记录；验证草稿中的凭证也单独加密，不放进返回给浏览器的识别结果。
密文绑定身份和来源/草稿 ID，复制到另一身份或来源不能直接使用。前端只在当前表单内存中暂存输入，验证后清空，不写入 localStorage。

Docker 使用独立 `source_secrets` 命名卷，实际项目卷通常为 `tiris_source_secrets`，密钥文件位于容器 `/run/tiris-secrets/source-key`。API 可写，Worker/Beat 只读。首次保存非空凭证时生成密钥；未保存真实凭证时可能不存在。
本机直接运行后端默认使用项目根目录 `.local-secrets/source-key`，该目录已被 Git 忽略；可通过 `SOURCE_CREDENTIAL_KEY_FILE` 指定其他位置。

备份必须同时包含数据库和密钥卷/文件，分开安全保管；不要执行删除数据卷的清理命令。只恢复数据库不能恢复凭证。缺少密钥、密文损坏或身份绑定错误时拒绝使用，不重新生成密钥冒充恢复成功；可恢复原密钥，或重新填写并验证新凭证。
加密仅保护数据库静态密文，不抵御整台主机或应用进程被控制。本项目没有登录鉴权，身份切换只是本地数据分区，不是用户权限边界，不能直接开放到公网。

旧来源保留 `legacy_env` 模式兼容 `.env` 中的 `GITHUB_TOKEN`；新来源使用 `stored` 或 `anonymous`。界面仅返回是否配置，不返回 Token 或密文。

## 当前边界与验收

目前只有 GitHub 平台 API 实现了网页凭证流程；其他平台需实现适配器，任意 API 不能只填 Key 自动理解。普通公开订阅继续无需凭证。
新连接凭证用于平台工具的查询和详情，尚未接入旧自动兴趣搜索任务，也没有自动同步 GitHub Star 到画像。初次预览只是公共仓库元数据，不代表相关资讯、README 全文或个性化推荐。

本轮 185 项后端测试、20 项浏览器测试通过，包含 Token 错误、保留/替换/移除、过期、身份隔离、加密与不回显等场景。真实容器匿名 GitHub API 验证取得 3 条预览；未使用用户真实 Token，认证成功与权限范围需要用户填入后实测。

可动手读 `backend/tests/test_platform_credentials.py`：输入假平台响应和模拟凭证，输出已验证草稿、加密来源配置及统一列表；重点学习“识别 ≠ 验证”“验证草稿 ≠ 保存来源”和密钥/密文分离。验收应同时确认成功配置可调用、失败不保存、返回值无凭证、换身份不可复用。
