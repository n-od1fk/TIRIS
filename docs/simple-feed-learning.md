# 连续资讯流与本地身份

侧边栏为今日推荐、资料库、来源、设置。没有登录或开发任务控制面板；开发接口仍在 `/docs`。
底部身份选择器直接切换数据空间；设置仍负责创建/命名身份和填写画像。

## 数据流与取舍

1. 设置保存长期画像，继续使用版本冲突检查。未显示的语言/阅读预算字段保留，固定栏目不改动。
2. 主界面 `GET /api/feed` 读取累积推荐；没有库存或滚动到底时 `POST /api/feed/refill` 提交有限补充任务。
3. 复用原采集、版本、规则/本地 Embedding 与 Celery；缓存还可用时继续匹配，外部刷新至少隔 15 分钟。单批 200 候选、10 推荐不是每日十条总上限。
4. 新推荐分页加入资讯流，不重复入队同版本。来源有限时等待，绝不保证无限真实资讯。关键词跨语言问题和推荐质量仍需人工评估。
5. 收藏仍是长期库门槛。资料库的更新提醒打开捕获变化的版本，不把抓取时间改变当材料更新。

`DiscoveryPanel.tsx` 是滚动、合并、补充状态与退避；`ItemCard.tsx` 是简洁卡片；`LibraryPanel.tsx` 汇总收藏与提醒。
`SettingsPanel.tsx` 管外观与身份；`ProfilePanel.tsx` 仅画像。`client.ts` 在请求中固定身份，切换时取消旧请求。
`SourcesPanel.tsx` 从统一 `/api/source-types` 读取类型、说明和地址提示，复用已有来源与任务接口，新增订阅/仓库/索引、启停和同步；任务未结束时每 3 秒读取状态，失败展示受控错误。
来源归属当前身份，新增后不会自动同步或收藏；点击同步获取候选，返回主界面按该身份画像匹配。
同步有新版本时可以跳过空推荐的退避，但外部自动刷新仍受 15 分钟间隔限制。
`backend/app/discovery/feed.py` 负责稳定分页与补充防重；`service.py` 保持单次工作预算；`tasks.py` 的 `feed_due` 每 15 分钟检查明确方向的本地画像。

## 小任务与验收

- 分页：输入至少 50 条隔离推荐，输出多页无重复、无遗漏。学习窗口函数、排序键与快照游标。第一页后插入新推荐，旧游标不掺入新记录；刷新才看到新记录。
- 补充：输入 32 条相关候选，连续完成两批，输出 20 条且只有第一次刷新外部来源；收藏仍为 0。学习队列活动锁、预算和退避。空批次不会无限请求。
- 身份：在两个身份下分别准备推荐和收藏，切换后输出各自的推荐、长期库、提醒和来源；切回后旧数据仍在。学习请求范围、组件重建与取消旧请求。新身份画像/收藏/来源都为空，来源需要主动添加。任何访问本服务的人都能切换标签，不能暴露到公网。
- 来源：输入名称、类型和有效订阅地址，输出当前身份下的新来源；同身份同类型同地址重复返回 409，其他身份可独立添加。点击同步后查看等待/运行/失败或完成状态；禁止跨身份操作来源。学习接口复用、任务轮询和错误边界。验收用隔离数据，不宣称真实 Black Hat 已抓取成功。
- 外观：切换暗色并刷新，仍为暗色。学习 CSS 变量、localStorage；外观只写浏览器，不改画像。

运行后端 `uv run pytest tests/test_feed_identities.py -v`；前端 `npm test`。
实际页面检查脚本 `node scripts/live-smoke.mjs` 会拦截自动补充，避免审查时启动个人任务；它不验证真实推荐质量。

## 未完成的边界

真实资讯供应是否足量仍取决于来源覆盖、更新和匹配；当前没有新增平台采集器、通用网页搜索或人工标注效果评估。
“添加来源”不是适配任意网页：博客需 RSS/Atom，GitHub 需具体仓库，Black Hat 只读公开索引且可能 403。
无账号密码、鉴权、AI 要点摘要、行为画像衰减、相邻探索、LangGraph、RAG 或排序训练。
未收藏候选可见期 30 天，但未物理清理正文/向量；没有磁盘硬上限。电脑和 Docker 停止时不持续工作。
