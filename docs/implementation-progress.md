## 阶段一 当前实现

模块化单体，保留现有 MIT 项目与 PostgreSQL 数据卷，独立实现采集代码，未复制 ReadPrism AGPL 代码。

| 能力 | 实现与验证范围 |
| --- | --- |
| 存储与迁移 | PostgreSQL + pgvector；Alembic 迁移与模型一致；隔离 schema 集成测试 |
| 来源管理 | RSS/Atom、GitHub 仓库、Black Hat 索引；添加、启停、同步、错误和历史记录 |
| 采集任务 | Celery + Redis，任务存数据库；初始尝试加最多 3 次重试；重复任务受锁和唯一约束保护 |
| 内容溯源 | 来源 ID、原始链接、规范化 URL、类型、语言、发布时间、抓取时间、获取范围、不可变版本 |
| 精确去重 | 规范化 URL；长全文、同标题、同类型、当前版本正文哈希相同才跨 URL 合并；保留所有来源关联 |
| 简单页面 | React + TypeScript + Vite；标题查询、来源筛选、分页、版本阅读、任务错误显示 |
| 安全读取 | HTTP/HTTPS、公网 IP 校验、每跳重定向重新校验、连接固定到校验 IP、保留 TLS SNI、限大小与超时 |
| 运行方式 | 本地开发或 Compose；本机端口；API 和 Worker 不以 root 用户运行；无初始化目录的 Windows 挂载依赖 |

Python 和前端依赖由 uv.lock/package-lock.json 锁定；Docker 基础镜像和 PostgreSQL/Redis 也固定到本次实际验证的 digest。升级依赖或镜像需重新跑迁移、安全读取与页面测试。

获取范围不是摘要质量评分：RSS 内容保守标为摘要/节选，即使 Feed 携带较长正文；GitHub 仓库仅元数据、未读取 README；Release 正文仅指 Release 说明，不是整个仓库；Black Hat 仅公开索引，不是演讲全文。未知发布时间留空。页面展示来源节选，不冒充 AI 要点总结。

每个来源维护自己的最近快照。两个来源交替同步不会反复生成相同版本；较短的新摘要也能保存，旧全文不删除。语义相似不触发合并，论文与代码等不同类型保留。主题簇关联展示尚未实现。

## 与草案的有意差异

1. 继续使用已验证的 Python 3.11，暂不为版本号更换环境；功能不依赖 3.12 特性。
2. 阶段一只新增 Redis 任务队列，不再新增数据库；Beat 留到需要定时同步/日报时，只启动一个实例。
3. 阶段一未引入 trafilatura、LLM 和 Embedding；阶段二本轮接入预训练向量模型，仍没有通用网页正文抓取、生成模型调用或 RAG。
4. 文档建议先 Python 状态机，但用户原始学习目标明确要求 LangGraph，后续任务 Agent 将采用 LangGraph 的真实工具选择、检查、补查与结束条件，不用多个 Agent 凑架构。
5. 初始只提供一个 RSS 和一个 GitHub 仓库；扩大来源、arXiv 与手动链接导入在后续实现。Black Hat 全字段（讲者、摘要、材料）仍需具体活动页面适配与可访问性验证。

## 阶段二 双后端语义检索

- 本地 `Qwen/Qwen3-Embedding-0.6B` revision `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`，CPU 推理；可选依赖单独安装，Compose 镜像包含 CPU 运行依赖。
- 百炼 `text-embedding-v4` 适配器：HTTPS 官方域名地址限制、明确外部发送同意、限批量与响应大小、超时、向量数量/维度/有限值校验、错误去敏、不重试或跟随重定向。
- `embedding_spaces` 按用户、模型、版本标签、端点、指令、1024 维与切分策略隔离；`embedding_chunks` 引用不可变资料版本；`embedding_jobs` 保留任务状态与已完成进度。
- 首版字符片段 600、重叠 100、每条最多 8 段，标题最多 200 字符；保存截断和材料范围。是有边界的检索基线，不是成熟的 token/语义 RAG 切分。
- 复用 Celery/Redis，默认每批 3 条、上限 20 条；每条资料原子写入，部分完成后失败可显式补建剩余资料；队列提交失败入库，崩溃需停 Worker 后手动恢复。
- 只检索当前配置空间与当前资料版本，片段精确余弦排序，每条资料返回一个最佳片段；来源过滤为空或无当前索引时不调用模型。
- 页面可切换后端、提交小批索引、查询、查看覆盖、范围与部分文本标记；无自动云端查询、无隐式跨模型回退、未发画像或行为数据。

真实验证：固定权重下载和 Windows CPU 示例调用成功；Docker 首批 3 条真实资料生成 17 个片段向量，任务成功。中文查询返回 3 个候选；初次 API 查询约 14.67 秒，包含该进程首次模型加载，仅为单次功能检查，不是稳定延迟基准或检索准确率。另通过实际页面的模型状态和桌面/手机 smoke。21 条资料及用户画像保留。

## 已知运行边界

仅适合本地单用户，没有登录鉴权，不可把端口直接暴露到公网。user_id 查询范围测试不等于完整多租户鉴权。

当前任务队列不是可靠事务发件箱。提交与消息发布之间进程崩溃、Worker 在执行中被强制关闭，可能留下活动状态。不能声称 exactly-once；须在停止 Worker 后使用 README 的 fail-job 命令恢复。后续再增加租约/发件箱与调度恢复。

每个 SafeHTTP 客户端按域名间隔请求；单实例单并发 Worker 避免普通队列任务同域并发。不要同时运行大量 CLI 同步，也不承诺跨进程的全局限速。系统 DNS 解析的最坏等待还取决于操作系统；DoH 模式有单次超时，但当前并非严格整个任务墙钟截止器。

精确副本判定较保守，不代表已经实现语义去重。UI、版本读取与失败展示已做自动化验证，长期使用可靠性、来源条款、跨版本分支、多源交叉更新还需继续验证。
